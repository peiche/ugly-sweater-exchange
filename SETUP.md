# Appwrite setup for Ugly Sweater Exchange

Do these steps once in the [Appwrite Console](https://cloud.appwrite.io/).
No real IDs are stored in this repo — copy each ID into your `.env` (locally)
and into Netlify's environment variables (for the deployed site).

## 1. Create a project

1. Appwrite Console → **Create project** → name it e.g. `Ugly Sweater Exchange`.
2. Copy the **Project ID** → `VITE_APPWRITE_PROJECT_ID`.
3. Note the endpoint. For Appwrite Cloud it depends on your project's region — this project (CCI) uses the Frankfurt endpoint `https://fra.cloud.appwrite.io/v1`
   → `VITE_APPWRITE_ENDPOINT`. (If you self-host Appwrite, use your own URL.)

## 2. Enable anonymous auth

Auth → **Settings** → enable **Anonymous** login. (Email/password, OAuth, etc.
stay off — the app only ever uses anonymous sessions, one per device.)

## 3. Create the database

Databases → **Create database** → name it e.g. `ugly-sweater-exchange`.
Copy the **Database ID** → `VITE_APPWRITE_DATABASE_ID`.

## 4. Create the three collections

Create each collection inside that database. For every collection, go to its
**Settings** and make sure **Document permissions** are enabled (per-document
permissions, not collection-level permissions) — the app sets permissions on
each document it creates.

### 4a. `exchanges`

Collection ID → `VITE_APPWRITE_EXCHANGES_COLLECTION_ID` (use `exchanges`).

| Attribute | Type | Required | Default / notes |
| --- | --- | --- | --- |
| `name` | String, size 80 | Yes | Exchange name |
| `spendingLimit` | String, size 20 | No | e.g. `$25`; empty = none |
| `exchangeDate` | String, size 20 | No | `YYYY-MM-DD`; empty = none |
| `joinCode` | String, size 6 | Yes | 6-char code, generated by the app |
| `organizerUserId` | String, size 36 | Yes | Anonymous user ID of the organizer |
| `organizerName` | String, size 60 | Yes | Organizer's display name |
| `drawn` | Boolean | Yes | Default `false` |

Add an **index** on `joinCode` (key index, type `key`) so lookups by code are fast.

### 4b. `participants`

Collection ID → `VITE_APPWRITE_PARTICIPANTS_COLLECTION_ID` (use `participants`).

| Attribute | Type | Required | Default / notes |
| --- | --- | --- | --- |
| `exchangeId` | String, size 36 | Yes | ID of the parent exchange document |
| `name` | String, size 60 | Yes | Participant's display name |
| `userId` | String, size 36 | Yes | Participant's anonymous Appwrite user ID |
| `hasViewed` | Boolean | Yes | Default `false`; set when they reveal their match |

Add an **index** on `exchangeId` (key index, type `key`).

### 4c. `assignments`

Collection ID → `VITE_APPWRITE_ASSIGNMENTS_COLLECTION_ID` (use `assignments`).
**This is the secret one.** No collection-level read permission should grant
broad access — the app sets per-document permissions on every assignment.

| Attribute | Type | Required | Default / notes |
| --- | --- | --- | --- |
| `exchangeId` | String, size 36 | Yes | ID of the parent exchange document |
| `giverUserId` | String, size 36 | Yes | Anonymous user ID of the person buying |
| `giverName` | String, size 60 | Yes | Giver's display name |
| `receiverUserId` | String, size 36 | Yes | Anonymous user ID of the person receiving |
| `receiverName` | String, size 60 | Yes | Receiver's display name |

Add indexes on `exchangeId` and on `giverUserId` (key indexes, type `key`).

## 5. Permissions — what the app sets per document

The Appwrite SDK sets these when creating documents; you do **not** need to
configure them by hand, but this is what to expect (and what makes the secret
work). Collection-level permissions should be left at their defaults with
document-level permissions enabled.

**One table-level permission you *do* need to set by hand:** on each of the
three tables, grant **Create** to the **All users** role (Security settings).
Appwrite only allows the Create permission at table level, not per document —
without it, anonymous users get `No permissions provided for action 'create'`
when the app tries to create a row. Leave Read, Update and Delete unchecked
at table level; those are governed by the per-document permissions below.

| Document | Permissions the app sets |
| --- | --- |
| **Exchange** | `read: any`, `update: user(organizer)`, `delete: user(organizer)` |
| **Participant** | `read: any`, `update: user(that participant)`, `delete: user(that participant)` |
| **Assignment** | `read: user(assignee only)`, `delete: user(organizer)` — the organizer deliberately gets **no** read permission |

Why `read: any` on exchanges and participants? Everyone needs to find an
exchange by its join code and see the "who's in" list. Those documents contain
no match information, so this is safe. The only documents that contain a match
are assignments, and those are locked to one user each.

> **Why assignments are written by a function, not the browser:** from a
> browser, Appwrite only lets a user grant document permissions to roles they
> own — `any`, all users, their own user ID, or teams they belong to. It
> cannot grant read access to *another* user, so a browser-side draw fails
> with `Permissions must be one of: (any, users, user:<own ID>, …)`. The draw
> function (`functions/draw`, Node 20, `node-appwrite`) runs server-side with
> an API key, which *can* grant each assignment to its assignee. It also
> handles redraw (reset) and delete-exchange, since the browser can't delete
> assignments it can't read.

## 6. The draw function

In the Appwrite console, under the same project:

1. **Create an API key** (Overview → Integrations → API Keys, or Settings →
   API Keys): name it e.g. `ugly-sweater-draw`, scopes **databases read** and
   **databases write** only. Copy the key — it is shown once.
2. **Create the function** (Functions → Create function): name
   `ugly-sweater-draw`, runtime **Node 20** (or newer Node), entrypoint
   `src/main.js`. Upload the contents of `functions/draw/` as the deployment
   (the console installs dependencies from `package.json` during the build).
   The function ID is shown on the function page — copy it.
3. **Set the function's variables** (Function → Settings → Variables):
   `APPWRITE_API_KEY` = the key from step 1 (mark it secret),
   `APPWRITE_DATABASE_ID` = the database ID from step 3 above. The table IDs
   default to `exchanges` / `participants` / `assignments` and only need
   variables if they differ.
4. **Activate the deployment** once the build succeeds, and run a test
   execution from the console with body
   `{"action": "draw", "exchangeId": "<an exchange ID>"}` — it should return
   `{"ok": true, ...}` only when run by the organizer; anyone else gets a
   403. (The function checks the calling user's ID against the exchange's
   organizer.)

## 7. Wire up the env vars

Copy `.env.example` to `.env` and fill in:

```bash
VITE_APPWRITE_ENDPOINT=https://fra.cloud.appwrite.io/v1
VITE_APPWRITE_PROJECT_ID=<project ID from step 1>
VITE_APPWRITE_DATABASE_ID=<database ID from step 3>
VITE_APPWRITE_EXCHANGES_COLLECTION_ID=exchanges
VITE_APPWRITE_PARTICIPANTS_COLLECTION_ID=participants
VITE_APPWRITE_ASSIGNMENTS_COLLECTION_ID=assignments
VITE_APPWRITE_DRAW_FUNCTION_ID=<function ID from step 6>
```

Then run `npm run dev` and create a test exchange. Add the **same variables**
in Netlify under **Site settings → Environment variables** and redeploy —
Vite bakes them in at build time, so changing them requires a rebuild.

## 8. Sanity checks

- Join the test exchange from a second browser (or a private window) with a
  different name — it should appear in the "Who's in" list.
- Draw names with 3+ test participants, then open the site in the second
  browser: you should see **only** that test person's match.
- Open the exchange as the organizer after the draw: you should see the
  status list, but no matches — not even your own, outside your reveal card.
- If you see "Not connected yet", an env var is missing or the site wasn't
  redeployed after setting it. If Appwrite returns a permissions error,
  double-check that document-level permissions are enabled on the collection.
